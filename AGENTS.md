# AGENTS.md — aplix code (`apc`)

## State of the repo (check before assuming anything)

v1.3 is the current milestone: a Cargo workspace (`crates/*`, 9 crates) whose crates all hold code —
`apc-core` (config + chat types), `apc-traits` (every trait), `apc-models` (HTTP adapters, SSE),
`apc-memory` (SQLite sessions with FTS5), `apc-decision` (heuristic guard + model store), `apc-tools`
(file tools + guarded shell), `apc-agent` (tool loop), `apc-plugins` (static registry) and `apc-cli`
(`init`, `config`, `run`, `chat` (REPL or full-screen view), `model`, `--version`). CI and tagged
cross-platform releases live in `.github/workflows/`. Hooks and context compaction do **not** exist
yet. Read the tree before assuming a module exists.

## Sources of truth

1. `SPEC.md` — authoritative for the **CLI MVP**: commands, priorities, traits, stack, decisions.
2. `README.md` — product vision and post-MVP roadmap.
3. `.ai-memory/` — accumulated knowledge; start at `index.md`.

On a technical detail, `SPEC.md` wins, and its §8 records every deliberate divergence from the
README *with the reason*. Don't "fix" a choice from §8 back to the README version without reading
why it was made. The README's Rust snippets are illustrative, not the contract; `.ai-memory/gotchas.md`
lists the known drift.

## Naming — easy to get wrong

- Repo name: `aplix-code` — **no crate is called that**. The binary crate is `apc-cli` with
  `[[bin]] name = "apc"`, so `cargo install --path crates/apc-cli` produces `apc`.
- Crate prefix is `apc-`: `apc-core`, `apc-traits`, `apc-agent`, `apc-tools`, `apc-decision`,
  `apc-models`, `apc-memory`, `apc-plugins`, `apc-cli` (the binary crate).
- Config file: `apc.toml`, generated by `apc init`.

## Architecture contract (SPEC §4 — keep it when scaffolding)

Cargo workspace, one job per crate, dependency direction outward from the bottom:

```
apc-core      shared types, errors, config — no internal deps
apc-traits    every trait (Model, Tool, MemoryStore, Decision, Plugin) — the plugin contract
apc-agent     agent loop, orchestration only, no I/O
apc-tools     built-in tools: read_file, write_file, list_dir, run_shell
apc-decision  Permission Guard: heuristic first, then open-jev (feature-gated)
apc-models    LLM adapters over direct HTTP + SSE (SPEC §8.10, no `genai`)
apc-memory    SQLite sessions with FTS5 search (+ JSONL import)
apc-plugins   static plugin registry (dynamic loading is v1.2)
apc-cli       the `apc` binary — composition root
```

Swappable behaviour goes behind a trait in `apc-traits`; never add a provider/backend-specific
dependency to `apc-agent` or `apc-cli`.

## Providers and streaming (v0.2)

- Two dialects only: OpenAI-compatible `POST {base_url}/chat/completions` and Anthropic
  `POST {base_url}/messages`. Adding a provider is one arm in `defaults()` in
  `crates/apc-models/src/lib.rs`; a provider that speaks a third protocol needs its own `Dialect`.
- **`base_url` is the directory that holds the version prefix** (`http://127.0.0.1:31415/v1`), because
  the adapter appends `/chat/completions`. Drop the `/v1` and you get the gateway's HTML page back.
- Typing in `apc-models` means the CLI's `ChatStream` errors arrive as items; the HTTP status and a
  non-`text/event-stream` body are errors *before* streaming starts. Don't "simplify" that check —
  without it a wrong base URL streams nothing and exits 0.
- Keys: `APC_API_KEY` first, then the provider's own variable (`OPENAI_API_KEY`, …). Ollama needs
  none. Keys are read at `build()` time and never written to config — `APC_API_KEY` is deliberately
  missing from `ENV_KEYS`.
- Anthropic needs `max_tokens` (constant) and its system prompt hoisted to a top-level field; the
  OpenAI dialect keeps `system` as a message. That split lives in `body()`.
- `apc chat` persists every exchange as it happens; `--continue` replays the most recent session.
- Debug builds read `./.env` through `load_dotenv` in `crates/apc-cli/src/main.rs`; release builds do
  not. The file is git-ignored and holds the local gateway URL, its key and the local Sentry DSN.

## Agent loop, tools and the guard (v0.3)

- `apc-agent::Agent::run` owns the ReAct loop: one streamed turn, then one tool execution per call,
  then the tool results go back as messages. It appends every turn to the `Vec<Message>` it is given —
  `apc-cli` persists the tail (`messages[before..]`) instead of re-deriving the exchange.
- A failing tool is a **message to the model**, never a crash: `execute` returns the error text as the
  call result, and an unknown tool name returns `unknown tool \`x\``. Only connecting to a provider or
  exceeding `MAX_STEPS` (8 tool rounds) is an error for the user.
- `RunShell` is the only path to a shell in the workspace. It asks the `DecisionProvider` first and
  only calls `Approver::confirm` when `risk > threshold` (strict `>`; a score of exactly 0.8 does not
  prompt — that is why `git push --force` scores 0.82). Declining returns a refusal string the model
  sees; the command is never spawned. If you add a tool that runs a process, it must take the same
  route — the guard lives in the tool, not in the CLI.
- `score()` is substring matching over a lowercase command, keeping the highest match: fast, and it
  stays the permanent fallback under the `open-jev` backend. Adding a pattern is one tuple in
  `PATTERNS` in `crates/apc-decision/src/lib.rs`; the true-positive test asserts `> 0.8`.
- Tools resolve paths lexically against the working directory (`..` and absolute paths are refused).
  Don't switch to `canonicalize`: the file may not exist yet, and the check must not depend on the
  filesystem.
- The CLI's `StdinApprover` reads the terminal synchronously inside the async fn. Deliberate: one
  flow, nothing else to run meanwhile. If a second concurrent tool call ever appears, revisit it.
- `apc-plugins::default_tools(root, decision, approver, threshold)` is what `apc-cli` asks for its
  tool set — keep hardcoded tool wiring out of the CLI.
- `Message` carries `tool_calls` / `tool_call_id`, and both dialects map them differently (OpenAI
  `tool_calls` + `role: tool`, Anthropic `tool_use`/`tool_result` blocks). Tool arguments arrive as a
  raw JSON **string** because that is how providers stream them; the agent parses them once.

## Roadmap boundaries (v1.2 → v2.1)

Kaneo holds one task per milestone, chained by `blocks` relations; ids are in `.ai-memory/workflows.md`.
Before starting one, read its acceptance criteria — they name the traps that bite:

- **v1.2** network tools: an unconfigured tool must not appear in the schema sent to the model.
- **v1.2b** decided — **refused** (SPEC §8.2). `rig` 0.46 was measured, not just read: MSRV 1.97.1 /
  edition 2024, `rig-reqwest`'s default `rustls` feature pulls `reqwest/rustls` (`aws-lc-rs`, the

  `rig-memory` is a non-optional dependency of `rig-agent`. The binary-size number could not be
  taken (crate bodies at ~2.8 KB/s, `aws-lc-sys` needs `cmake`), which is itself the §8.10 story.
  Never let `rig` types rise above `apc-models`/`apc-agent`; if hooks ever land, copy
  `DispatchAction::Deny` rather than importing the crate.
- **v1.3** long-term memory — **done**: `apc-memory` is `SqliteStore` over
  `memory.db` (FTS5 via `rusqlite` 0.39 `bundled`), and `new()` imports any existing
  `sessions/*.jsonl` first. `rusqlite` **was** absent from this machine's cargo cache (a ~46 KB/s
  download, not the 3 KB/s of the rig spike), and 0.40 dropped `bundled` while 0.41 needs Rust 1.89
  — do not bump without checking both.
- **v2.0** `apc serve`: axum 0.7 and tauri 2.11 *are* cached; loopback + token, guard over the API.
- **v2.1** sandboxing: `landlock`, `wasmtime` and `extism` are **not** cached either.

Cache absence is not fatal — it costs a slow download (~3 KB/s here) — but it must be disclosed
before a task starts, not discovered mid-build.

## Chat view (v1.1)

`crates/apc-cli/src/tui.rs` draws the full-screen view with `ratatui` + `crossterm`; the plain REPL
still exists in `main::repl` and must keep working.

- **Dispatch**: `tui::available()` = stdin *and* stdout are terminals. Piped input (every CLI test,
  every script) takes the REPL, so a change to the view must never break `chat_persists_a_session_…`.
- **One source of truth for history**: each turn reloads the session from `SqliteStore` and persists
  what the agent appended, instead of threading `Vec<Message>` through the view.
- **The guard runs inside the agent task and blocks.** `TuiApprover` sends the question over a
  `std::sync::mpsc` channel; the render loop polls `try_recv()` every tick and answers on `y`/`n`.
  Never `recv()` that channel from the async loop — it would freeze the view.
- `Paragraph::line_count` is **private** in ratatui 0.29; the scroll offset comes from the small
  `wrapped_height` helper. `Style::new().red()` does not exist either — use `Style::default().fg(…)`.
- Test it through a real pty: `script` alone leaves the window 0x0 and ratatui draws nothing, so set
  `TIOCSWINSZ` (see `.ai-memory/commands.md` for the driver script).

## Intent classification and skills (v1.1)

- `apc_decision::classify(prompt)` (`crates/apc-decision/src/intent.rs`) is **heuristic only**: a
  lowercase substring match over `KEYWORDS`, and the keyword appearing **earliest** wins, so "ajoute
  un commentaire" is code generation, not an explanation. No model, like the guard.
- `Intent::skill()` maps to a file stem under `skills/`; `Intent::Other` has none.
- `apply_skill` in `crates/apc-cli/src/main.rs` reads `./skills/<stem>.md` and puts it at index 0 as
  a system message, replacing any previous one. It is **not persisted**: `apc chat` reloads the
  session every turn and re-derives it, and `before` is captured after the insert so the persisted
  slice still starts at the user's prompt. A missing file means no system prompt, never an error —
  that is what keeps `apc` working in a project without `skills/`.
- Only `apc-cli` does this I/O; `apc-agent` stays prompt-neutral.

## Web tools (v1.2)

- `crates/apc-tools/src/web.rs` holds `WebSearch` (SearXNG, `GET {base}/search?q=…&format=json` →
  `results[].title/url/content`, 5 results by default, 10 max) and `FetchPage` (plain `reqwest`
  `GET`, then `rs-trafilatura` extracts the main content as Markdown, and `truncate()` cuts on a
  char boundary saying how many bytes were dropped). Use the crate rather than a hand-rolled tag
  stripper: it keeps code fences and drops nav/footer, which a stripper cannot.
- `rs-trafilatura` costs ~4.2 MB of release binary (3.9 → 8.1 MB) because it embeds its XGBoost page
  classifier; the 15 MB gate still holds, but re-measure before adding another model-bearing crate.
  In **debug** builds it prints `DEBUG:` lines on stderr (`cfg!(debug_assertions)`); release is
  silent, so don't "fix" those prints.
- **Both are config-gated, in different ways.** `tools.searxng_url` unset (`APC_SEARXNG_URL`) means
  `web_search` is not built at all — an unconfigured tool must never reach the schema the model is
  offered, and `crates/apc-cli/tests/cli.rs::an_unconfigured_search_tool_is_never_offered_to_the_model`
  pins that. `fetch_page` needs no service, so it is always registered; only `tools.fetch_max_bytes`
  (65536) tunes it.
- `apc_plugins::default_tools(root, decision, approver, config)` takes the whole `&Config` now: the
  threshold and the tool URLs come from one place, and adding a tool stops growing the parameter list.
- `fetch_page` is **not** Obscura: `obscura serve` speaks CDP (WebSocket) only, no WebSocket crate is
  cached offline, and the `obscura` crate builds V8 from source. The reasoning, and
  `obscura mcp --http` as the way back, are in `SPEC.md` §8.13. Don't reintroduce an
  `obscura_url`-style key without a backend that actually honours it.
- `reqwest` gained the `query` feature for `.query(&[..])`; that is the only dependency change.

## Session memory (v0.2b, SQLite since v1.3)

- `apc-memory::SqliteStore` is what the CLI opens: `ProjectDirs::from("dev","aplix","aplix")
  .data_dir()/memory.db`. Never hardcode `~/.local/share`; the CLI tests point `XDG_DATA_HOME` at
  their sandbox for exactly this reason.
- Schema: `sessions(id TEXT PRIMARY KEY)`, `messages(id INTEGER PRIMARY KEY AUTOINCREMENT, session,
  body)` holding the JSON-encoded `Message`, and `messages_fts`, an FTS5 table over `messages.body`
  with `content='messages'` kept in step by the `messages_indexed` AFTER INSERT trigger. Adding a
  message goes through the `messages` table only — the index follows.
- A session id is `{:013}-{:06}` (unix seconds, microseconds), so `ORDER BY id DESC` is
  chronological and "latest" needs no stat calls.
- `MemoryStore::load(None)` means "the most recent session". `search(query, limit)` returns
  `Recall { session, snippet }`; the store quotes each word of the query (`"foo" OR "bar"`) and
  ranks with `messages_fts.rank`. A query with no word of three characters or more returns nothing.
- `apply_memory` in `apc-cli` puts the three best recalls from **other** sessions in front of the
  prompt as one system message, merging into an existing one. A store that errors is not fatal: the
  turn proceeds without recall.
- `SqliteStore::new()` imports `<data dir>/sessions/*.jsonl` before serving: sessions already in the
  database are skipped, lines that do not parse are dropped (an interrupted append leaves a torn
  tail), and the JSONL files are left untouched — nothing deletes user data.
- One connection behind a `Mutex`; poisoned locks are recovered, because the CLI is
  single-flowing and a poisoned mutex here means one bad query, not corrupt data.
- `MemoryStore` stays async although these calls are tiny.

## Config — the shipped feature

- `apc-core::config` owns the schema and the precedence order; `apc-cli` only wires paths, env vars
  and flags into `Layer`s. Don't reimplement precedence in the CLI.
- A new key needs three edits: the `Config`/section struct, `TEMPLATE` (what `apc init` writes), and
  its `Default` — `template_matches_the_defaults` and `defaults_layer_covers_every_key` enforce it.
- In `TEMPLATE`, top-level keys (`telemetry`) must stay **above** the first `[table]`; TOML puts
  everything after `[provider]` inside it.
- `deny_unknown_fields` is deliberate: a typo in `apc.toml` must fail loudly, not be ignored.
- Layers: defaults < user (`~/.config/aplix/apc.toml`, via `directories`) < `./apc.toml` <
  `./apc.local.toml` < `APC_PROVIDER` / `APC_MODEL` / `APC_BASE_URL` / `APC_PERMISSION_THRESHOLD` /
  `APC_DECISION_ENDPOINT` / `APC_TELEMETRY` < flags. `apc config` prints the winning layer per key.

## Constraints that come from the product promise (do not silently break)

- **Local-first micro-decisions.** Safety checks and intent/context decisions run on a local
  model (`open-jev`, quantized DeBERTa-v3, ~350 MB, `q4f16`) in <20 ms, never a cloud call. The
  **heuristic fallback ships first and always exists**: `apc` must work with no model downloaded
  (that is why `open-jev` is a feature flag, SPEC §8.1, and why it is a sidecar client, §8.11).
- **Every `run_shell` goes through the Permission Guard**; `P(destructive) > 0.8` ⇒ explicit user
  confirmation. Configurable threshold. No bypass path in `apc-agent` or `apc-tools`.
- **Streaming is in the trait** (`chat → ChatStream`, i.e. `Stream<Item = Result<ChatEvent>>`), not
  bolted on later (SPEC §8.3, §8.10).
- **V1 `apc chat` is a plain stdin/stdout REPL** — no `ratatui`, no panes (SPEC §8.6).
- **No dynamic plugin loading in V1**: `apc-plugins` is a static registry; `Plugin`/`MemoryStore`
  traits exist for V1.2 (SPEC §8.7, §9).
- **No telemetry, analytics or phone-home** — one exception, opt-in Sentry error reporting
  (SPEC §3.4, §8.9): no DSN shipped, `APC_TELEMETRY=0` wins over any DSN, `warn`/`error` only,
  never file/prompt content, initialised in `apc-cli` alone.
  - **`telemetry` is opt-in at build time**: `default = []`, so a normal `cargo build` carries no
    Sentry code. To work on it, build or test with `--features telemetry` (CI has that shape) and
    set `telemetry = true` plus a DSN. Debug builds also read `.env` (`load_dotenv`), release builds
    never do.
  - Verified at v1.0: the release binary has no sentry crate in its graph, no DSN string, and with
    `SENTRY_DSN` + `APC_TELEMETRY=1` forced in the environment it still opens no connection.
  - The dev DSN in `.env` is Rustrak (`rustrak-api.applix.fr`, project 3 "Aplix code"). Delivery can
    be checked without the UI through the `senntry-online` MCP: `list_projects` →
    `list_issues({project_id: 3})` → `list_events`/`get_event`. A `warn!` becomes an *event* (level
    `warning`), not just a breadcrumb, and its `error` field carries file paths.
  - `panic = "abort"` means panic events only reach Sentry in debug builds.
  - The `tracing` subscriber (fmt layer to stderr) is installed unconditionally, so
    `APC_LOG=debug|info|warn|error` gives local logs with no DSN and no network; default is `warn`.
    It is `with_target(false)`, so third-party `debug` events (hyper, reqwest) also print.
  - Cost of the feature (`strip` + `lto`): 7 377 912 B with `--features telemetry` vs 5 914 328 B
    without — the HTTP stack, not Sentry, dominates. Still inside the 15 MB budget, but re-measure
    whenever a dependency is updated.
  - Measured at v1.3: the release binary without telemetry is 10 054 128 B, up ~1.9 MB from
    8 147 656 B — bundled SQLite is that cost, and it is the price of the no-system-dependency
    promise. Still 5.6 MB below the gate.
- **CI is the contract** (`.github/workflows/ci.yml`): `fmt`, `clippy -D warnings` and `test` in
  **three feature shapes** — default, `--features open-jev`, `--features telemetry` — plus a
  release build on Linux/macOS/Windows with a 15 MB size gate (`wc -c` < 15728640, `apc.exe` on
  Windows). Reproduce a failure with the same shape locally before pushing; a shape you did not
  run is a shape that can fail in CI.
- **Release artifacts are built `--no-default-features`** (`.github/workflows/release.yml`, tags
  `v*`): published binaries contain no Sentry code, so no event can leave a release even with
  `SENTRY_DSN` set. `default = []` has been the case since the release task; never put
  `telemetry` back in `default`.
- **`#![forbid(unsafe_code)]` in every crate, no exception** in V1 (SPEC §8.8).
- **Binary < 15 MB**, models downloaded on demand (resumable + SHA-256 verified), never bundled.
  Release profile: `lto`, `codegen-units = 1`, `strip = "symbols"`, `panic = "abort"`,
  `opt-level = 3` — size comes from stripping, not from `opt-level = "z"` (SPEC §8.5).
- Config precedence: defaults < user < project < local < env < flags. Config file `apc.toml`; API
  keys from env only.
- Rust 1.80+ minimum, no system dependency: TLS is `rustls` with the **ring** provider.
  reqwest is built with `rustls-no-provider` because its default `aws-lc-rs` C sources reference
  glibc 2.38 symbols and refuse to link on Ubuntu 22.04 (the release runner). Every crate that
  builds a `reqwest::Client` calls `apc_core::net::install_crypto_provider()` first — a client
  created without it panics with "No rustls crypto provider is configured". The Linux release
  artifact is built on `ubuntu-22.04` so it runs on glibc 2.35 (Ubuntu 22.04, Debian 12).

## Commands

```bash
cargo build --offline                    # this machine cannot reach crates.io at usable speed
./target/release/apc --version
cargo test --workspace
cargo test -p apc-core config            # single crate / single test (substring match)
cargo test -p apc-cli --test cli         # CLI end-to-end, incl. a local SSE stub server
cargo test -p apc-memory                 # SQLite round trip, FTS5 search, JSONL import, read-only db
cargo test -p apc-decision               # guard patterns + the resumable model download
cargo test -p apc-tools                  # path confinement + a refused confirmation runs nothing
cargo clippy --all-targets -- -D warnings
cargo fmt --check
cargo build --no-default-features        # compiles the Sentry feature out
```

The CLI tests spawn `CARGO_BIN_EXE_apc` with a throwaway `HOME`/`XDG_CONFIG_HOME` and clear the
`APC_*` variables, so they never read your real `~/.config/aplix/apc.toml` or your `.env` (the child's
working directory is a temp sandbox, so `./.env` is absent). Keep them that way: a test that depends
on the developer's config is flaky. Network calls are faked with a one-shot `TcpListener` serving a
canned SSE body — never call a real provider from a test.

If CI is added, it becomes the source of truth for this list.

## Decision backends (v0.3b)

- The `open-jev` cargo feature is **off by default** and lives in `crates/apc-decision`; `apc-cli`
  re-exports it as `open-jev = ["apc-decision/open-jev"]`.
- `JevProvider` (`crates/apc-decision/src/jev.rs`) is an HTTP **client** for a local-jev sidecar —
  the model is not embedded, because no inference runtime or weights are available offline
  (SPEC §8.11). A user runs `local-jev` themselves and sets `decision.endpoint` /
  `APC_DECISION_ENDPOINT` (e.g. `http://127.0.0.1:8080`).
- `P(destructive)` is read from `probabilities[option == "yes"].probability`, **never** from
  `confidence`: confidence describes whichever option won, so a confident `no` would read as a high
  risk. local-jev's own `noul` route classifies instead of answering yes/no, hence the
  `choice(["no","yes"])` mapping.
- A **flat** answer is treated as no opinion: local-jev v2.0.0 without weights answers `0.5 / 0.5`
  to everything, and reading that as "low risk" let `rm -rf` through unconfirmed (reproduced, then
  fixed). `flat()` in `jev.rs` errors when the two best probabilities are within 0.01, so the
  heuristic answers; keep that guard when adding another backend.
- `Cascade` is fail-open by design: any transport, status or JSON error falls back to
  `HeuristicProvider` silently. That is what keeps SPEC §2.3 true — a dead sidecar must not block
  `apc`. Tests cover both directions (working backend wins, broken one falls back).
- Verify with `cargo test --offline -p apc-decision --features open-jev`. `reqwest` is unconditional
  now (the model store uses it); only `serde_json` and `jev.rs` sit behind the feature.

## Model store (v0.4)

`crates/apc-decision/src/store.rs` holds the catalog, the downloader and the verifier. **`CATALOG`
is empty on purpose**: `local-jev` publishes no weights (SPEC §8.11), so there is nothing to fetch
and the heuristics remain the only working guard. Do not invent a URL or a SHA-256 to make
`apc model download` succeed — `apc model list` saying "nothing is published" is the honest state
(SPEC §8.12).

Rules if you touch it:
- A model is `<data dir>/models/<id>.bin`; a download is `<id>.bin.part` and only `rename`s after
  the byte count matches `entry.bytes` **and** the SHA-256 matches. Never install an unverified file.
- A server that answers `200` to a `Range` request gets its file truncated and restarted, not
  appended to.
- A checksum mismatch deletes the `.part`: a corrupt partial cannot resume into a good file.
- `reqwest` and `sha2` are unconditional dependencies of `apc-decision`; only `open-jev`'s
  `serde_json` is feature-gated.
- Tests use a one-shot `TcpListener` that honours `Range` (and one that ignores it). No real
  network in a test, ever.
