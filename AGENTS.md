## Naming — easy to get wrong

- Repo/package: `aplix-code`. Binary and CLI name: **`apc`** (so `[[bin]] name = "apc"`).
- Crate prefix is `apc-`: `apc-core`, `apc-traits`, `apc-agent`, `apc-tools`, `apc-decision`,
  `apc-models`, `apc-memory`, `apc-plugins`, `apc-cli` (the binary crate).
- Config file: `apc.toml`, generated by `apc init`.

## Architecture contract (SPEC §4 — keep it when scaffolding)

Cargo workspace, one job per crate, dependency direction outward from the bottom:

```
apc-core      shared types, errors, config — no internal deps
apc-traits    every trait (Model, Tool, MemoryStore, Decision, Plugin) — the plugin contract
apc-agent     agent loop, orchestration only, no I/O
apc-tools     built-in tools: read_file, write_file, list_dir, run_shell
apc-decision  Permission Guard: heuristic first, then open-jev (feature-gated)
apc-models    LLM adapters via the `genai` crate
apc-memory    JSONL session store (+ future backends)
apc-plugins   static plugin registry (dynamic loading is v1.2)
apc-cli       the `apc` binary — composition root
```

Swappable behaviour goes behind a trait in `apc-traits`; never add a provider/backend-specific
dependency to `apc-agent` or `apc-cli`.

## Constraints that come from the product promise (do not silently break)

- **Local-first micro-decisions.** Safety checks and intent/context decisions run on a local
  model (`open-jev`, quantized DeBERTa-v3, ~350 MB, `q4f16`) in <20 ms, never a cloud call. The
  **heuristic fallback ships first and always exists**: `apc` must work with no model downloaded
  (that is why `local-jev` is a feature flag, SPEC §8.1).
- **Every `run_shell` goes through the Permission Guard**; `P(destructive) > 0.8` ⇒ explicit user
  confirmation. Configurable threshold. No bypass path in `apc-agent` or `apc-tools`.
- **Streaming is in the trait** (`chat → Stream<Response>`), not bolted on later (SPEC §8.3).
- **V1 `apc chat` is a plain stdin/stdout REPL** — no `ratatui`, no panes (SPEC §8.6).
- **No dynamic plugin loading in V1**: `apc-plugins` is a static registry; `Plugin`/`MemoryStore`
  traits exist for V1.2 (SPEC §8.7, §9).
- **No telemetry, analytics or phone-home** — one exception, opt-in Sentry error reporting
  (SPEC §3.4, §8.9): feature `telemetry`, off by default, no DSN shipped, `APC_TELEMETRY=0` wins
  over any DSN, `warn`/`error` only, never file/prompt content, initialised in `apc-cli` alone.
- **`#![forbid(unsafe_code)]` in every crate, no exception** in V1 (SPEC §8.8).
- **Binary < 15 MB**, models downloaded on demand (resumable + SHA-256 verified), never bundled.
  Release profile: `lto`, `codegen-units = 1`, `strip = "symbols"`, `panic = "abort"`,
  `opt-level = 3` — size comes from stripping, not from `opt-level = "z"` (SPEC §8.5).
- Config precedence: defaults < user < project < local < env < flags. Config file `apc.toml`; API
  keys from env only.
- Rust 1.80+ minimum; OpenSSL or `rustls` (feature) is the only system dependency expected.

## Roadmap order (SPEC §7 — do not jump ahead of it)

v0.1 skeleton + `apc init`/`apc config`/config resolution → v0.2 `run`/`chat` via `genai` with
streaming → v0.3 Permission Guard (heuristic, then `open-jev`) → v0.4 `apc model` + downloads →
v1.0 MVP. TUI (`ratatui`, v1.1), intent classification, `skills/`, SearXNG/Obscura (v1.2),
long-term memory (v1.3), `apc serve` + Tauri (v2.0), sandboxing/WASM (v2.1) are all **post-MVP** —
don't scaffold them for an MVP task.
