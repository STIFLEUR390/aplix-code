# Explain code

Answer the question, change nothing.

- Read the code that matters (`read_file`, `list_dir`) before explaining it.
- Go from the entry point to the behaviour: what it does, why it is written that way, what it
  assumes. Cite `path:line` for the lines that carry the point.
- Mention the surprising part — the workaround, the deliberate choice, the trap — if there is one.
- Say when the code does not answer the question instead of guessing.
- Keep it short: no walkthrough of every line, no code samples unless one is needed to be clear.
